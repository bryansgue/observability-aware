# Identifiability-Aware Virtual Force Sensing and Self-Calibration for Quadrotors

A quadrotor rarely carries a force sensor, but flying in wind or carrying a
payload needs the external force. This code turns the onboard **IMU into a
virtual force sensor**: the external specific force is read directly from the
accelerometer residual of the flight estimator.

The catch is calibration — the residual gives force only if the mass is known,
and near hover the mass is **unidentifiable**: a vertical force and a mass
change look identical, so a standard EKF quietly corrupts the mass. The
estimator here is **identifiability-aware and self-calibrating**:

- an online **identifiability measure** — the marginal Fisher information on
  the mass (a closed-form Schur complement over a 1-s window) — **gates the
  calibration and freezes the mass when it cannot be seen**;
- when the flight lacks excitation, the controller injects a **minimal probe**
  (a bounded excursion of the position reference, not a sensor), triggered and
  shaped by the same measure, and withdrawn once the mass is recovered.

The sensed force feeds an NMPC as feedforward, improving tracking under wind.
All results are MuJoCo software-in-the-loop at 100 Hz.

*Identifiability-Aware Virtual Force Sensing and Self-Calibration for

## How it works

1. **Reading.** The specific-force residual of the estimator gives the external
   force in the world frame: `d = R·a_imu − (T/m)·R e₃ − g e₃`. It is a vector,
   instantaneous, and valid at zero velocity — unlike an energy balance.
2. **Identifiability test.** Over a sliding 1-s window, the normalized Schur
   complement `σ̃` of the information matrix isolates exactly the
   mass–vertical-force coupling. It is zero in stationary hover (provably) and
   grows with the dispersion of the thrust vector.
3. **Gate.** While `σ̃ < σ̃_min = 0.009` (plus a dwell), the mass update is
   frozen; the force keeps being estimated. The plain EKF, without the gate,
   trades mass error for force error exactly where the force matters most.
4. **Probe.** If the mass is needed and `σ̃` stays below threshold, the
   controller adds a bounded reference excursion (budget 0.8 m; a vertical bob
   is the most informative shape) until the gate has been open for 15 s, then
   withdraws it and holds the identified mass.
5. **Feedforward.** The smoothed force enters the NMPC dynamics
   (`v̇ = (T/m̂)·R e₃ + d̂ + g`), so the controller anticipates the wind instead
   of only reacting. Mass and `d̂` are runtime solver parameters — no rebuild.

An MHE with the same models was implemented as a check: it does not improve on
the EKF (the model is nearly linear in the estimated states), so the EKF is the
estimator of record and the MHE remains as a comparison.

## Requirements

- ROS 2 Humble
- [acados](https://github.com/acados/acados) (solver; generated C code included
  under `c_generated_code_*`)
- Eigen 3
- MuJoCo simulator workspace (`~/mujoco_ws`) with the MujocoRosUtils plugin —
  the paper's data are reproduced with the plugin state committed 2026-06-18
  (`mujoco_ws` commit `31ef534`)
- Python 3 + numpy/matplotlib for the analysis scripts

## Build

```bash
cd build
source /opt/ros/humble/setup.bash
source ~/mujoco_ws/install/setup.bash
cmake --build . --target nmpc_mhe_sil -j$(nproc)
```

## Reproduce

Start the noisy scene + wind node (publishes ground truth on
`/quadrotor/external_force`) in another terminal:

```bash
MUJOCO_ODOM_NOISE=1 sim_gate_collideroff
```

Single runs (from `build/`):

```bash
./nmpc_mhe_sil v2 60 w=2.0          # force sensing (known mass)
./nmpc_mhe_sil v2 60 w=2.0 ff       # + feedforward d̂ → NMPC (rejection)
./nmpc_mhe_sil v2 60 w=2.0 idmass   # wrong mass prior → identification
./nmpc_mhe_sil v2 60 hover ff       # windy hover (max rejection)
```

`v1` = open loop (fixed wrong mass), `v2` = closed loop. The NMPC tracks a fixed
time reference, so any tracking change is the estimator alone — a clean ablation.

Paper batteries (each = one experiment group; every run resets and verifies the
sim before flying, and aborts rather than relaunching a broken simulator):

| Script | Experiment | Paper output |
|---|---|---|
| `scripts/batch_rejection.sh` | speeds × {ff, baseline} | Figs. 11–12 (rejection), Fig. 10 |
| `scripts/batch_trans.sh` | gated vs plain EKF, maneuver→hover | Fig. 7 |
| `scripts/batch_active50.sh` | probe vs passive recovery, 50-s runs | Fig. 8 |
| `scripts/batch_probe_sweep08.sh` | probe shape sweep at 0.8-m budget | Fig. 9 |
| `scripts/batch_robust.sh` | accel bias/scale + thrust error sweep | Fig. 13 |
| `scripts/batch_sens.sh` | gate sensitivity, 100 runs, one knob at a time | Table 7 |

Analysis/plotting: `scripts/analyze_*.py` and `scripts/plot_*.py` read the CSVs
from `results/` and write the figures used in `paper/figs/`.

Useful environment knobs: `ACCEL_NOISE` (accelerometer noise level),
`PROBE_OPEN_TIME` (gate-open seconds before probe withdrawal),
`EKF_WIN` / `EKF_DWELL` / `EKF_RS` (gate window, dwell, measurement noise).
